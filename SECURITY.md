# Security Policy

## Supported versions

The `main` branch is the active development line. No release-support schedule or response-time guarantee is currently published.

## Reporting a vulnerability

Please do not publish exploit details, credentials, private data, or weaponized proof-of-concept material in a public issue.

1. If GitHub's **private vulnerability reporting** feature is enabled for this repository, use it to submit a report privately.
2. If that feature is unavailable, contact the repository owner through the contact route on the GitHub profile and request a private reporting channel.
3. Include the affected file or component, impact, reproduction conditions, and suggested mitigation. Do not include real credentials or third-party personal data.

This repository does not currently advertise a dedicated encrypted security endpoint or a guaranteed response-time commitment. Those will only be added if an operational reporting channel and response process are established.

## Scope and safe harbor

Only test systems and data that you own or are explicitly authorized to assess. Do not access, alter, exfiltrate, or disrupt third-party systems. Good-faith reports should minimize data access and avoid destructive testing.

## Data-quality and privacy issues

For incorrect public-record mappings, unsupported allegations, exposed personal information, or provenance concerns, report the affected record identifier and source privately where appropriate. Avoid reposting sensitive data in public issues.
